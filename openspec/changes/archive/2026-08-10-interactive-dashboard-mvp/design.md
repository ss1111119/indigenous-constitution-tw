## Context

專案目前沒有任何前端程式碼，唯一的原始碼是 scripts/extract-cec-elprof.ps1（中選會選舉資料解析）。可行性研究已完成兩輪核實，結論為值得做，資料基礎確認可用。

資料現況（皆已下載並存於 data/raw/）：

| 資料 | 來源 | 最細層級 | 更新 |
| --- | --- | --- | --- |
| 人口與原住民身分 | 戶政司 ODRP013 | 村里（7,771 列） | 月，滯後約 2 個月 |
| 人口按族別 | 戶政司 ODRP018 | 村里，26 族欄位 | 月 |
| 歷屆立委選舉 | 中選會 votedata | 山原／平原／區域 | 每次選舉 |
| 原住民保留地 | 原民會 CSV | 縣市（僅 13 個） | 不定期 |

三個貫穿全案的資料事實，直接決定介面設計：

1. **選舉區不是行政區**。原住民立委選舉區是全國性的山地／平地兩區，無法對應縣市，因此選舉面板無法隨地區選擇器變動。
2. **保留地只有 13 個縣市有資料**。其餘縣市是「無保留地」而非「資料缺漏」。
3. **平埔族群欄位存在但值為 0**，且該欄位自民國 114 年 11 月（2025-11）才出現。2025-10 以前欄位根本不存在。

## Goals / Non-Goals

**Goals:**

- 四個面板呈現人口、選舉、土地、席次模擬，可於 GitHub Pages 靜態託管
- 每個顯示在畫面上的數字都能追溯到 data/sources.json 的一筆來源，並標示其性質
- 「無資料」「零」「未登記」三種狀態在畫面上可區辨，不混為一談
- 席次模擬器將未決的政策參數暴露給使用者，不替其預設立場
- 無 build step，無 node_modules，專案生命週期以年計，維護成本優先於開發便利

**Non-Goals:**

- GIS 圖層（原住民保留地範圍、傳統領域）。授權需向 TGOS／國土測繪申請，狀態未確認，列為第三階段
- 各族人口點陣分布圖。中研院 CAPAS 已有 10K 解析度成果，本站外連而非重做
- 遷徙 Sankey 與傳統部落地圖。中研院 TIPsMigDynamics 與 iqTICD 已涵蓋
- 村里層級的地圖呈現。7,771 個多邊形對儀表板過深，且村里 GeoJSON 取得不易
- 面板間的任意交叉篩選。僅有一個全域地區選擇器作為共享狀態
- 使用 CDN 載入函式庫。外部相依在專案生命週期內可能失效

## Decisions

### 決策一：全域地區選擇器作為唯一跨面板共享狀態

**選擇**：頂部一個「全國／縣市」選擇器，人口與土地面板隨之變動；選舉與模擬面板固定為全國。

**理由**：原住民立委選舉區在資料層就不是行政區，強行讓選舉面板連動會做出「點了沒反應」的介面，那比不連動更糟。

**替代方案**：地圖點選驅動全部面板 — 否決，同上理由，且成本高。四面板完全獨立各有篩選 — 否決，使用者需自行在腦中交叉比對，失去儀表板的意義。

### 決策二：地理層級為縣市加鄉鎮下鑽

**選擇**：預設顯示 22 縣市，可下鑽至該縣市的鄉鎮。

**理由**：鄉鎮層才看得到「原住民族地區」這 55 個法定鄉鎮，以及原鄉與都市原住民的對比 — 那是本題目的核心張力之一。

**替代方案**：只做縣市 — 否決，看不到原鄉差異。做到村里 — 否決，見 Non-Goals。

### 決策三：席次模擬器暴露三個控制項

**選擇**：平埔納入人口滑桿、保障席次滑桿、增額與重分配的切換。另兩個未決參數（平埔是否計入原住民選舉人名冊、是否另立族別類別）寫成畫面上可展開的明示假設。

**理由**：「增額或在 113 席內重分配」不是參數而是兩套不同的算式 — 113 席內重分配是零和的（原住民增一席則區域減一席），增額則否。把它藏起來等於代替使用者選了一種制度設計。另兩項僅影響細部計算，明示假設即可。

**替代方案**：五個參數全開 — 否決，介面複雜且後兩項法制未決，使用者難以判斷。只留兩個滑桿 — 否決，等於偷偷選了零和那一種。

### 決策四：平埔納入人口滑桿上限為 637,620，並標註參照點

**選擇**：上限設為現有原住民人口 637,620。刻度上標示兩個有出處的點：0（官方現況）與 50,000（專家學者評估，且僅為西拉雅族首年登記推估）。兩者之間與之外的區間以視覺標示為無官方或學術依據。

**理由**：滑桿上限本身就是一種主張，使用者會將其讀為「最多可能這麼多」。使用有出處的真實數字作為參照點，語意是「平埔納入後原住民人口翻倍」，而非宣稱平埔人口有這麼多。

**替代方案**：上限設為 50,000 — 否決，無法回答「若九族全部納入」這類問題，而那正是模擬器存在的理由。改為數字輸入框 — 否決，失去標註參照點的機會。

### 決策五：土地面板以所有權變遷為主

**選擇**：主圖為國有與私有面積的逐年變化，標示民國 112 年的黃金交叉；使用類型組成降為次要。

**理由**：實測資料顯示保留地總面積幾乎不變，但民國 110 至 113 四年間約 6,400 公頃由國有轉為私有，且 112 年私有首度超過國有。此趨勢與原住民族土地權主軸直接相關，且目前無人視覺化。使用類型組成則到處都有。

**替代方案**：以使用類型為主 — 否決，資訊價值中等。兩者並列 — 否決，兩張圖訊息強度差距大，並列會稀釋主圖。

### 決策六：轉檔時注入來源識別與欄位性質

**選擇**：data/sources.json 維持唯一真實來源；轉檔腳本將 `_sourceId` 與欄位層級的 `_fieldNature` 寫入每支 processed JSON。前端讀 processed JSON 即可標示性質，僅在使用者要求詳情時才載入 data/sources.json。

**理由**：現行 data/processed/legislative-representation.json 的 meta.derived 是中文散文，前端要做欄位級標示就得解析句子。注入結構化欄位可免除 runtime join 與字串解析。

**替代方案**：前端 runtime 讀 sources.json 對應 — 否決，每頁多載一支含大量網站用不到的 notes 的檔案。只做面板級來源標示 — 否決，放棄了三分法在介面上的落實。

### 決策七：純 HTML 加 CSS 加 JavaScript，函式庫納入版本庫

**選擇**：不使用框架與 build step。圖表用 Chart.js，地圖用 Leaflet，兩者以本機檔案形式提交進版本庫。議會席次圖手寫 SVG。

**理由**：決策一將共享狀態收斂為單一變數，用不著框架的狀態管理。本站生命週期須撐過 2028 年 10 月的立法期限，無 build step 意味著無 CI、無相依版本腐爛。CDN 在多年尺度上有失效風險。

**替代方案**：Vite 加 React 或 Vue — 否決，為單一共享狀態引入框架是本末倒置。D3 — 否決，本站無需自訂座標系。ECharts 或 Plotly — 否決，單檔 1MB 起跳。

## Implementation Contract

### 行為

**轉檔管線**：執行轉檔腳本後，data/processed/ 產生聚合至縣市與鄉鎮兩個層級的 JSON。腳本在寫檔前執行自我驗證，任一驗證失敗則中止並回報，不得產生檔案。

**儀表板**：於瀏覽器開啟 site/index.html 後顯示四個面板。變更頂部地區選擇器時，人口與土地面板重新渲染為該地區資料；選舉與模擬面板不變，並在面板上標示其為全國資料。

**席次模擬器**：調整任一控制項後，代表性指標與議會席次圖即時重算。初始狀態為現況（平埔納入人口 0、保障席次 6、113 席內重分配）。

**溯源**：點選任一數字可看到其來源機關、資料基準日與性質標籤。

### 資料形狀

processed JSON 的共同外層：

```
{
  "_sourceId": "moi-odrp018-11506",
  "_generatedBy": "scripts/build-population.ps1",
  "_generatedAt": "2026-08-10",
  "_fieldNature": {
    "population": "official-statistic",
    "ratio_pct": "derived-by-this-project"
  },
  "data": [ ... ]
}
```

`_fieldNature` 的值域限於 data/sources.json 的 schema.nature 所定義者。data 陣列中每列以 district_code 為鍵，縣市層級為 5 碼，鄉鎮層級為 8 碼。

**一個 processed JSON 只能有一個 `_sourceId`**，因此來自不同 endpoint 的資料**分檔輸出**，不得併入同一檔。人口資料據此拆為 population-by-county（源自 ODRP013）與 tribes-by-county（源自 ODRP018），鄉鎮層級同理。併檔會迫使單一 sourceId 涵蓋兩個來源，即為本專案禁止的來源混用。

`_fieldNature` 的分類判準見 data/sources.json 的 schema 內 natureRule 一欄：本專案計算值的定義是**官方從未發布過這個數字**，而非是否經過計算。原住民族人口雖需相加三欄才得到，但原民會月報有直接發布且已交叉驗證，故為官方統計。

### 失敗模式

| 情境 | 行為 |
| --- | --- |
| 轉檔自我驗證失敗（男加女不等於合計，或原住民加非原住民不等於總計） | 中止並回報差異數值，不產生檔案 |
| 中選會欄位版面偵測失敗 | 中止並回報，不套用預設版面 |
| 選取的縣市無保留地資料 | 土地面板顯示「此縣市無原住民保留地」，非空白亦非零 |
| 平埔欄位值為 0 | 顯示「尚無登記」，非空白亦非 N/A |
| 時間序列涵蓋 2025-10 以前 | 平埔數列在該區間不繪製，亦不繪為 0 |
| 保留地時間序列缺民國 108、109 年 | 該區間斷線，不做內插 |
| processed JSON 載入失敗 | 該面板顯示錯誤訊息與來源網址，其餘面板正常運作 |

### 驗收條件

1. 執行人口轉檔腳本後，data/processed/population-by-county.json 的全國合計為 23,243,565，原住民合計為 637,620，與 data/raw/ 中的 ODRP013 快照相符
2. 族別資料的 16 族合計等於 637,620，10 個平埔族群欄位皆為 0
3. 土地資料民國 113 年所有權部總計為 265,766.858 公頃，國有為 128,762.884 公頃
4. 席次模擬器初始狀態的席次占比顯示 5.31%，人口占比顯示 2.74%
5. 將保障席次滑桿設為 6 且平埔納入人口設為 0 時，輸出與現況數字一致
6. 選取一個無保留地的縣市（例如新竹市），土地面板顯示「此縣市無原住民保留地」
7. 每個面板上至少一個數字可點選並顯示來源、日期與性質三項資訊
8. 在瀏覽器停用 JavaScript 時，index.html 仍顯示可讀的說明文字與資料來源清單

### 範圍界線

**在範圍內**：轉檔腳本、聚合、溯源注入、四面板、全域地區選擇器、席次模擬器、縣市與鄉鎮 GeoJSON。

**在範圍外**：保留地範圍圖層、傳統領域圖層、村里層級呈現、面板間任意交叉篩選、資料自動更新的排程機制、多語系。

## Risks / Trade-offs

- **中選會格式無預警變更且不更新格式文件** → 轉檔腳本內建版面偵測與自我驗證，偵測失敗即中止而非套用預設；已於 docs/data-spine-check.md 記錄四個實測陷阱
- **戶政司 API 路徑參數易誤用**（民國年月而非民國年） → 於腳本註解與 data/sources.json 記錄正確格式；本專案第二輪曾因此誤判資料不存在
- **平埔登記開始後數字快速變動，快照迅速過期** → 轉檔腳本以 yyymm 為參數，可重跑任一期；data/raw/ 保存登記前的基準快照
- **使用者將滑桿上限誤讀為平埔人口上限主張** → 刻度標註有出處的參照點，無依據區間視覺標示，並於面板文案明述上限為參照點而非主張
- **兩個原住民人口占比並存造成誤解**（2.74% 為 2026-06 戶籍現況，2.51% 為 2024 選舉區人口） → 趨勢線僅繪至 2024，現況數字獨立呈現，兩者間有視覺區隔與口徑說明
- **Chart.js 與 Leaflet 納入版本庫增加庫容量** → 接受。相較於 CDN 在多年尺度上失效的風險，這是划算的交換
- **鄉鎮 GeoJSON 檔案量體影響載入** → 預設僅載入縣市層級，下鑽時才載入該縣市的鄉鎮

## Migration Plan

專案為全新建置，無既有系統需遷移。

部署：**GitHub Pages 從 repo 根目錄發布**，網站入口為 `/<repo>/site/`。

⚠️ 此段於實作 3.2 時更正。原本寫「Pages 指向 site/ 目錄」，但 **GitHub Pages 只支援 repo 根目錄或 /docs 兩個選項**，無法指向任意資料夾。且前端以相對路徑 `../data/` 讀取資料，若發布根目錄設在 site/，資料就落在發布範圍之外，線上必然 404。

從 repo 根目錄發布可同時解決兩者：`site/index.html` 位於 `/<repo>/site/`，其 `../data/` 正好解析為 `/<repo>/data/`。代價是網址多一層 `site/`，換得零改動與零 build step。

現有 docs/ 目錄維持研究文件用途 — 此決定取代可行性研究 E 節「將研究文件移至 research/」的建議，因為網站改用 site/ 後不再有衝突。

回退：靜態站，回退即還原至前一個 commit。

## Open Questions

1. 洪雅族（hoanya）在戶政司官方欄位中存在，但不在已提出申請的 9 族名單內。模擬器的「哪些族納入」選項是否列出洪雅族，待釐清該欄位存在的原因後決定。暫定作法為依官方欄位清單呈現全部 10 族，並於文案註明申請狀態差異。
2. 縣市與鄉鎮 GeoJSON 的具體來源與授權尚未確認，需於實作前選定一份可再利用的公開圖資。
3. 原民會人口月報的授權條款未明（頁尾僅有概括版權聲明）。本案主來源為授權明確的戶政司資料，月報僅作交叉驗證用，故不阻塞；但若日後要在畫面上直接呈現月報數字，須先釐清。
