## Context

平埔族群欄位自 2025-11 起存在於戶政司 ODRP013／ODRP018，值恆為 0。西拉雅族於 2026-07-30
獲核定為第 17 族，身分登記自 2026-08 中開放，期別 11508 很可能是第一期非零。

轉檔腳本對兩個來源的處理已經正確：ODRP013 的原住民合計定義為山地、平地、平埔三者相加；
ODRP018 只取主清單 27 欄（16 現行族＋10 平埔族群＋未申報），不碰平行的平埔交叉表欄位，
並以「族別加總等於原住民合計」的自我驗證守住。前端人口面板也已有 absent／zero／registered
三態，且刻意只依載入的資料判定、不看日期。

出問題的是**消費端對這些欄位的假設**：席次模擬器把原住民合計當成「不含平埔」使用，
文案把 0 當成永久現況。這些假設在平埔恆為 0 的十個月間都成立。

## Goals / Non-Goals

**Goals:**

- 平埔非零時，模擬器的人口基數與官方統計一致，且滑桿歸零時重現官方現況
- 站台不再有任何寫死的平埔人口數值作為現況陳述
- 人口面板的合計敘述與實際加總範圍一致
- 非零平埔的成功路徑進入回歸測試

**Non-Goals:**

- 不重新設計長條圖（平埔是否從獨立區塊移入長條）
- 不做逐月時序保存
- 不處理管線中 absent 三態是否可達
- 不調整席次制度模型（併入現行類別或自成一類，法律未定）

## Decisions

### 基數公式改為先扣除已登記平埔再加滑桿值

模擬器目前以各縣市 `indigenous_total` 累加得到現有原住民人口，再直接加上滑桿值。
由於 `indigenous_total` 已含平埔，已登記者被計入兩次。

改為：先由同一份資料的平埔欄位算出已登記平埔人口，從基數中扣除，再加滑桿值。
亦即滑桿值代表**納入保障體系的平埔人口總數**，而非「額外新增的人口」。

選擇這個做法而非「滑桿代表額外人口」的理由：後者要求使用者自行知道官方已登記多少、
再自行決定要額外加多少，把一個減法作業推給讀者；而且滑桿上限（現有原住民人口）
與參考點（學術估計的首年登記數）都是以「平埔人口總數」為尺度標示的，改成增量會使
既有的參考點標示失去意義。

副作用是現況預設值不再是 0 而是「目前已登記數」。平埔為 0 時此值為 0，
與現行行為完全相同，因此不影響 11508 之前的呈現。

### 現況起點由資料導出而非常數

現況預設值、滑桿參考點標示、以及「目前官方登記數」的敘述，一律由載入資料的平埔欄位導出。
判定依據只用資料本身，不看當前日期或登記開放日——與人口面板三態判定同一原則，
理由相同：ODRP 發布滯後約兩個月，以日期判定會在資料尚未發布時宣稱有登記數。

### 移除「首次」的時序宣稱

人口面板已登記狀態的敘述宣稱這是官方統計中首次出現的平埔登記人口。站台載入的是單一期別
的資料，沒有歷史期別可比對，因此**無法從資料判定該期是否為第一個非零期別**。

在時序產出物存在之前，任何「首次」宣稱都只能寫死，而寫死的宣稱不會自己失效。
故移除時序宣稱，改為不含先後主張的敘述。待逐月時序變更完成後，若屆時有判定依據，
再行恢復。

### 現況判定與滑桿零點是兩件事

現行程式以「滑桿為零」判定現況。依上述公式，滑桿為零在平埔非零時代表的是
「不把已登記平埔納入保障體系」的反事實情境，不是現況。現況判定須改為
「滑桿等於已登記平埔人口」，否則初始畫面數字正確、卻仍被標示為模擬結果。

平埔為零時兩者重合，行為與現行相同。

另須注意人口比例的現況基準仍應使用官方原住民總數（已含平埔），不可改用扣除平埔後的基數——
扣除只用於避免滑桿值重複相加，不是對官方現況的重新定義。

### 動態官方參考點必須同時動態化其溯源

滑桿的參考點目前是靜態字串常數，數值與說明文字都寫死。官方參考點改為由資料導出後，
該數值須比照站台其他數字掛上來源識別、欄位性質與期別，否則會出現「數字動態了、
溯源仍是靜態文案」的不一致——那正是本專案資料紀律第 3 條要防的情況。

參考點的位置與標籤都須使用動態值，不能只替換數值而保留寫死的期別描述。

### 滑桿級距與已登記數可能不對齊

滑桿以千人為級距。已登記平埔人口不必然是千的倍數（首批登記很可能是三位數），
初始值因此可能不是合法的級距值。實作須明確處理這個情況並以非千位數值測試，
不得讓瀏覽器自行調整初始值而使畫面數字與官方數字不符。

### 法制事件的「首例」不在移除範圍

時間軸中描述西拉雅族成為第 17 族的「平埔族群首例」，講的是法律認定事件，
不是統計資料中的首個非零期別。該敘述有明確依據且不會失效，維持不動。
驗收時以搜尋方式檢查「首次」殘留者，須排除這一處。

### 頁尾敘述明確涵蓋範圍

頁尾宣告合計等於原住民人口總數時，須指明合計涵蓋的是圖表中的各族、未申報，
以及圖表下方獨立區塊呈現的平埔族群，使該句在平埔以獨立區塊呈現時仍然正確。
不改變加總本身——加總目前即為正確。

### 非零平埔樣本的構造方式

新增一組回歸樣本，以既有的全零成功樣本為基礎，將部分人口移至平埔欄位，
使兩個來源同時成立：ODRP013 的山地、平地、平埔三者相加等於原住民合計；
ODRP018 的主清單 27 欄相加等於同一個原住民合計。平行的平埔交叉表欄位維持與主清單
不一致的值，以確保若實作誤用交叉表欄位，樣本會失敗而非碰巧通過。

## Implementation Contract

**行為**：在平埔非零的資料下，模擬器初始畫面呈現的原住民人口、人口比例、席次比例，
與人口面板依同一份資料呈現的官方數字一致；使用者未移動任何控制項時，模擬結果即為官方現況。
移動滑桿時，人口基數不因已登記平埔人口而重複增加。

**資料介面**：模擬器與人口面板讀取的欄位不變。模擬器新增讀取縣市層級的平埔人口欄位，
該欄位由轉檔腳本產出、性質標記為官方統計。不新增任何檔案格式或資料契約。

**失敗模式**：資料中不存在平埔欄位時（歷史期別），已登記平埔人口以零處理，
模擬器行為與現行完全相同；此情況不得產生錯誤或警示，因為欄位不存在是合法的歷史狀態。

**驗收**：
- 回歸測試新增的非零平埔樣本通過，且既有四組樣本結果不變
- 以非零平埔資料在瀏覽器檢視，模擬器初始的原住民人口數等於人口面板的原住民總數
- 站台原始碼中不存在以平埔人口數值書寫的現況陳述
- 頁尾敘述在非零平埔下所指涉的範圍與加總欄位一致

**範圍界線**：
- 範圍內：模擬器人口基數與現況導出、人口面板兩處敘述、非零平埔回歸樣本與斷言
- 範圍外：長條圖形式、時序保存、管線 absent 三態、席次制度模型

## Risks / Trade-offs

- **[滑桿語意改變可能被讀者誤解為新功能]** → 滑桿標籤與參考點說明維持現有措辭；
  改變的只有起點取值來源。平埔為 0 時畫面與現行完全相同，無可察覺差異。

- **[以既有樣本改造出的非零樣本可能與真實 11508 結構不同]** → 樣本用於驗證恆等式與
  消費端邏輯，不用於驗證真實數值。真實資料的正確性另由轉檔自我驗證與人工交叉驗證把關。

- **[移除「首次」會失去一個有新聞價值的敘述]** → 這是刻意的取捨：寫死的「首次」在
  11509 之後就是假話，而站台的資料紀律不允許為了敘述效果保留已知會失真的陳述。
