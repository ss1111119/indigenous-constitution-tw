## Context

資料目錄頁對每筆來源並列「提供者的授權宣告」與「本專案的再利用判斷」，
後者取自 `data/sources.json` 的 `reusable`（值域 true / false / unknown），
以「本專案判斷可再利用」這類結論呈現，並附一段說明其射程的警語。

25 筆來源中，20 筆的授權是明確的開放授權，5 筆不是：
非開放授權但本專案判斷可用的（原民會月報）、無授權宣告的（CAPAS TPDD）、
以軟體授權涵蓋資料的（CAPAS TIPD，GPL 3.0）、兩個平臺說法不一致的（原民會教育調查統計）、
以及本專案自行彙整而內含第三方引述的（西拉雅基線）。

## Goals / Non-Goals

**Goals:**

- 頁面不再對讀者給出可被讀成許可的結論
- 授權清楚的來源不因多一層判斷而增加雜訊
- 需要當心的少數來源在版面上看得出來
- 新增的資料欄位保持最小，不觸發 notes 的全面結構化

**Non-Goals:**

- 不改 `reusable` 的語意或值域
- 不做 notes 全面結構化
- 不重新評估任何來源的授權判斷
- 不移除警語

## Decisions

### 授權是否明確由資料判定，不由人工逐筆標記

判斷一筆的授權是否為明確開放授權，依 `license` 欄位的內容判定：
命名了已知的開放授權文件、且未同時出現否定或未定的措辭者，視為明確。

不新增「這筆授權清不清楚」的布林欄位：那會是第二個需要人工維護的判斷，
與 `license` 欄位本身重複，且兩者一旦不同步，頁面會顯示與授權文字相反的分類。
由 `license` 導出則不可能不同步——它就是同一個事實。

新增來源若使用尚未被認得的授權名稱，會落入「不明確」一側，
頁面因此顯示本專案的用法欄位；該欄位若未填，退回只顯示宣告。
這個方向是刻意的：認錯成「需要當心」的代價，遠小於認錯成「授權清楚」。

### 新欄位陳述行為，不陳述結論

新增欄位記錄的是本專案**做了什麼**——取得方式、是否改動、是否再散布、是否註明出處——
而不是「能不能再利用」。措辭一律為動作，例如「逐字複製、未改動、註明出處，未改作」。

理由是形式決定讀法。一個叫做「可再利用」的欄位，無論旁邊寫多少警語，
都會被讀成對讀者的許可；一句描述行為的話則需要讀者自己去對照條款，
而那正是這件事本來就該由讀者自己做的判斷。

欄位只填需要的來源，不強制每筆都有。授權清楚者填了也不會顯示。

### 未填時退回只顯示宣告，不顯示殘缺內容

新欄位缺漏時，該筆只顯示提供者的宣告。不顯示「未記載」之類的佔位文字——
在授權這件事上，一個空欄位的正確處置是不說話，而不是說「我們沒說」。
說了反而像是宣稱本專案審視過而無可奉告。

### 需要當心的來源在版面上可辨

那 5 筆會因為多一段「本專案的用法」而在版面上與其餘不同。
此外於該區塊加上與資料缺口相同的警示邊框，使讀者不展開條目也看得出哪幾筆情況特殊。

不另外做篩選器或分頁：25 筆的規模用不上，且把它們抽離原本的清單反而
會讓讀者以為那是另一類資料。

### 頁首警語隨之改寫

現行警語說「本專案的再利用判斷不是給你的授權」。改為說明兩件事：
多數來源的授權由機關自己宣告；少數來源另附本專案的實際用法，供讀者對照條款自行判斷。

警語不移除——它現在說明的是版面規則，而不是替一個誤導的結論打補丁。

## Implementation Contract

**行為**：讀者在目錄頁看到的每筆來源都顯示提供者的授權宣告。
授權為明確開放授權者，不顯示任何本專案的判斷或用法。
其餘來源另顯示一段描述本專案實際用法的文字，並在版面上與其他來源可區分。
頁面任何位置不出現可被讀成「讀者可以再利用」的結論性措辭。

**資料介面**：`data/sources.json` 新增一個記錄本專案實際用法的字串欄位，
於 schema 說明其語意為「陳述本專案做了什麼，不陳述能不能做」。
`reusable` 欄位保留，語意不變，供登記檔內部使用。既有欄位的值不更動。

**失敗模式**：新欄位缺漏時，該筆退回只顯示提供者的宣告，不顯示佔位文字、
不顯示 `reusable` 的值。授權名稱無法辨識時，該筆歸入需要當心的一側。

**驗收**：
- 授權為明確開放授權的 20 筆，頁面上皆無本專案的判斷或用法段落
- 其餘 5 筆皆顯示本專案的用法，且該文字不含許可性結論
- 全頁不出現「可再利用」「不可再利用」這類結論措辭
- 移除某筆的新欄位後，該筆退回只顯示宣告，且不出現任何殘缺文字
- `data/sources.json` 除新增欄位外，其餘欄位的值與變更前逐字相同

**範圍界線**：
- 範圍內：新欄位與其 schema、5 筆的內容、目錄頁授權區塊的呈現、警語措辭、對應的檢查
- 範圍外：`reusable` 的語意、notes 結構化、任何來源的授權判斷本身、篩選或分頁功能

## Risks / Trade-offs

- **[由 `license` 文字導出「是否明確」，措辭改變時分類會跟著變]** →
  這正是要的行為：授權文字是同一個事實的來源，分類跟著它變才不會不同步。
  且方向偏保守——認不得的授權會被歸入需要當心的一側。

- **[讀者可能仍然誤讀「本專案的用法」為許可]** → 無法完全排除，
  但描述行為的句子沒有主張可以引用，讀者要據以行動必須自己做一次對照，
  那一步正是責任轉移的分界。

- **[20 筆不再顯示本專案的判斷，等於少了一項資訊]** → 該資訊仍在
  `data/sources.json` 中可查。對讀者而言，機關已明確授權時，
  本專案的判斷不改變他能做什麼。
