## 1. 轉檔腳本輸出機器可讀標記

- [x] 1.1 依 design 決策「腳本輸出機器可讀標記，訊息維持不變」，轉檔在幅度檢查實際執行時輸出一行固定格式、與語言無關的標記，內容含觀察到的變動百分比與是否經放行；既有中文訊息一字不改。無可比基準而略過檢查時不輸出標記。驗證方式：以既有 success（通過）、amplitude-jump 加放行參數（放行）、以及無 previous 的無基準情境各跑一次，比對標記的有無與內容。

- [x] 1.2 回歸測試涵蓋標記的三種情況：幅度檢查通過時有標記且百分比正確、具名放行時標記標明已放行、無可比基準時不輸出標記。既有以中文訊息斷言的案例維持不變，證明訊息與標記並存。驗證目標：`pwsh tests/run-regression.ps1` 的離開碼與新增斷言列。

## 2. 流程改以標記溝通

- [x] 2.1 滿足 A legitimate large change is released by a named human override 新增的解耦要求：刷新流程判斷是否放行、以及取得變動百分比，皆解析標記而非比對中文訊息。驗證方式：以搜尋確認 workflow 檔案中不存在對轉檔腳本中文訊息的比對；並確認措辭改寫不影響流程行為（在本機以改過訊息措辭的腳本副本重跑解析邏輯）。

- [x] 2.2 滿足 The observed change is reported on every run that computes it：幅度檢查執行時，觀察到的百分比一律寫入流程摘要，不限放行時；無可比基準而略過時不報百分比並說明已略過。commit 訊息在非放行時維持原格式，依 design 決策「幅度只進流程摘要，不進非放行的 commit 訊息」。驗證方式：以三種情境（帶內變動、放行、無基準）比對摘要輸出與 commit 訊息內容。

- [x] 2.3 幅度檢查執行了卻找不到標記時，流程大聲失敗而非以空值繼續；無基準而無標記則屬正常、不得失敗。驗證方式：以缺少標記的合成輸出餵入解析邏輯，確認前者中止、後者通過。

## 3. 訊息組裝與其驗證

- [x] 3.1 依 design 決策「訊息組裝與提交決策分離」，滿足 The commit message is assembled whether or not a commit follows：訊息組裝移出「有 diff」分支，一律組裝並寫入流程摘要；是否提交仍只依 diff 決定，部署觸發條件不變。驗證方式：以既有期別重跑，確認摘要可見組出的訊息且未產生提交、未觸發部署。

- [x] 3.2 依 design 決策「渲染驗證用合成輸入，不碰真實資料」，新增訊息渲染驗證，直接以合成的百分比與理由驗證組裝結果，不經轉檔、不產生資料檔。涵蓋正數、負數、小數百分比與含換行的理由，斷言訊息含幅度與理由原文，且未放行時不含放行段落。驗證目標：該測試的離開碼與各案例斷言列。
