## Context

刷新流程與轉檔腳本之間目前以「人類可讀的中文訊息」溝通：腳本用 Write-Host 印出
幅度檢查結果，workflow 把資訊串流併入成功串流後，以字串比對判斷是否被放行，
再用正規式從訊息中挖出百分比。

這個耦合在開發期間一直有效，因為兩邊由同一個人同時維護。但它有兩個性質使它在
關鍵時刻特別危險：措辭是文案（隨時可能為了可讀性被改寫），而消費它的路徑
只在變動超過 ±1% 時才執行——至今從未發生。

西拉雅族登記自 2026-08 中開放，11508 預計 2026-09 初發布，可能是首次觸發。

## Goals / Non-Goals

**Goals:**

- 流程與腳本之間的溝通不再依賴文案措辭
- 百分比擷取在每一次排程執行中都被真實運行，而非只在放行時
- commit 訊息組裝可在不產生提交的執行中被觀察
- 訊息組裝的邊界情況有測試涵蓋

**Non-Goals:**

- 不改變非放行時的 commit 訊息格式
- 不調整 ±1% 門檻，也不新增調整途徑
- 不以合成資料產生任何會被提交的資料
- 不做平埔登記逐月時序

## Decisions

### 腳本輸出機器可讀標記，訊息維持不變

轉檔腳本在既有的人類可讀訊息之外，另外輸出一行固定格式的標記，內容包含
變動百分比與是否經放行。既有中文訊息一字不改——它服務的是讀流程紀錄的人，
不該為了機器解析而犧牲可讀性；反過來機器也不該去讀為人寫的字。

標記一律輸出，但兩種情況的形狀不同：幅度檢查實際執行時，標記帶百分比與放行與否；
無可比基準而略過時，標記只標明「已略過」而**不帶百分比**——此時並不存在「觀察到的變動」，
輸出空值或零會與「變動確實為 0%」混淆。

略過時仍須輸出標記（而非完全不輸出），否則流程只能靠比對中文的「幅度檢查略過」來分辨
「略過了」與「腳本壞了沒印東西」，那正是本變更要消除的耦合。

選擇新增標記而非改寫既有訊息，是因為改寫會同時破壞既有的回歸斷言
（測試以「幅度檢查通過」「幅度檢查失敗」等字串斷言）與流程紀錄的可讀性。

### 幅度只進流程摘要，不進非放行的 commit 訊息

擷取到的百分比一律寫入流程摘要，使解析每次都被執行。但 commit 訊息維持現狀：
非放行時不附幅度。

理由是語義而非篇幅：每次提交都帶幅度會把例行更新混入診斷欄位，
更嚴重的是會讓「幅度曾被計算」在版本歷史中看起來像「曾被放行」，
而放行是需要人負責的行為，它在歷史中的可辨識度不該被稀釋。

### 訊息組裝與提交決策分離

目前訊息組裝寫在「有 diff」的分支內，因此以既有期別重跑時完全不會執行。
改為一律組裝、一律寫入流程摘要，是否提交仍只依 diff 決定。

這使得以既有期別手動觸發成為一次真正的演練：可以看到組出的訊息長什麼樣，
而不會產生提交或觸發部署。

### 渲染驗證用合成輸入，不碰真實資料

新增的測試直接以合成的百分比與理由驗證訊息組裝，不經過轉檔、不產生資料檔。
涵蓋正數、負數、小數、含換行的理由，以及未放行時訊息不得含放行段落。

這是唯一能在真實大幅變動發生前驗到組裝本身的方法。它驗不到「腳本確實在超過門檻時
輸出放行標記」——那需要真實的幅度事件，本變更不宣稱涵蓋。

## Implementation Contract

**行為**：刷新流程在每一次成功轉檔後，於流程摘要呈現觀察到的變動百分比；
在有無提交的情況下都呈現組裝出的 commit 訊息。實際提交與部署的條件不變。
放行時 commit 訊息仍含幅度與理由原文。

**介面**：轉檔腳本新增一行機器可讀標記輸出，格式固定且與語言無關，
內容為變動百分比與放行與否。workflow 解析該標記取得兩項資訊，
不再比對任何中文字串。標記在幅度檢查未執行（無可比基準）時不輸出。

**失敗模式**：幅度檢查執行了卻找不到標記，視為流程與腳本不同步，應大聲失敗而非
以空值繼續——沿用現行「找不到百分比即 throw」的處置。無可比基準而無標記
屬正常情況，不得失敗。

**驗收**：
- 回歸測試涵蓋標記的存在與格式（通過、放行、以及無基準時不輸出三種情況）
- 訊息渲染驗證涵蓋正負與小數百分比、含換行理由、未放行時不含放行段落
- 以既有期別在真實 Actions 手動觸發一次，流程摘要可見百分比與組裝訊息，且無提交、無部署
- workflow 檔案中不存在對轉檔腳本中文訊息的比對

**範圍界線**：
- 範圍內：腳本的標記輸出、workflow 的標記解析與摘要輸出、訊息組裝位置、渲染驗證
- 範圍外：門檻值、commit 訊息在非放行時的格式、平埔時序、真實大幅變動的端對端驗證

## Risks / Trade-offs

- **[新增標記使腳本輸出多一行，可能被誤讀為新的使用者資訊]** → 標記格式刻意不像人話，
  且流程紀錄中緊鄰既有的中文訊息，讀者不會把它當成主要資訊。

- **[渲染驗證用合成輸入，驗不到腳本與流程的實際銜接]** → 銜接由回歸測試的標記格式斷言涵蓋；
  兩者相加仍不等於一次真實的大幅變動，此限制明白記錄，不宣稱已驗證。

- **[以既有期別演練無法觸發放行分支]** → 演練的目的是驗證標記解析、摘要輸出與訊息組裝，
  不是驗證放行判斷本身。放行判斷的首次真實執行仍會發生在真實事件當下，
  屆時未驗證的面積已縮小到「條件式附加那兩行」。
