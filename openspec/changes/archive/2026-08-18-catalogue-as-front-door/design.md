## Context

站台目前根網址是儀表板（`index.html`，四個面板 + 區域選擇器 + 席次模擬器），
資料目錄是 2026-08-18 新增的 `data.html`，入口只在儀表板頁尾的一句話裡。

專案的主張是臺灣原住民族開放資料——盤點資料的取得方式、授權、陷阱與缺口。
儀表板是用其中幾份資料做出來的分析。目前的結構把佐證放在最前面、主張放在最後面。

組建流程有一道與此衝突的檢查：`substitute_period` 硬性要求 `index.html` 含
`{{DATA_PERIOD}}`，找不到就刪除 `_site/` 並中止。它防的是基準日回到寫死狀態。
而資料目錄沒有單一基準日——25 筆來源各有各的 `dataDate`，因此它當首頁時
本來就不該有那個佔位符。

## Goals / Non-Goals

**Goals:**

- 根網址呈現資料目錄
- 儀表板在自己的網址上完整運作，行為不變
- 兩頁互連，任一頁都不需經由另一頁才能使用
- 首頁文案與分享卡片描述資料盤點
- 基準日檢查改為指向儀表板，且原本要防的事仍然成立

**Non-Goals:**

- 不改儀表板的內容與行為
- 不改資料目錄的內容與行為
- 不改 `data/sources.json`
- 不做重新導向
- 不重寫可行性研究

## Decisions

### 以檔案更名互換，儀表板落在 dashboard.html

`site/index.html` 的內容（儀表板）移至 `site/dashboard.html`；
`site/data.html` 的內容（資料目錄）移至 `site/index.html`。`data.html` 不再存在。

網址結果：

| 網址 | 內容 |
| ---- | ---- |
| `/` | 資料目錄 |
| `/dashboard.html` | 四個面板 |
| `/data.html` | 404 |

選擇讓 `data.html` 消失而非保留為重複內容：同一份內容有兩個網址會分散外部連結、
讓搜尋引擎需要判斷何者為正、且兩邊的 canonical 必然有一邊在說謊。
`data.html` 於 2026-08-18 才上線、僅存在數小時，外部幾乎不可能已有連結指向它。

用檔案更名而非新建：儀表板頁的內容一位元組都不必改（除了互連與網址標記），
更名讓 git 記錄成 rename，之後追這頁的歷史仍然連得起來。

### 基準日檢查改為明列「必須含佔位符的頁面」清單

`substitute_period` 目前寫死檢查 `index.html`。改為**明列一份頁面清單**
（目前只有儀表板頁），對清單上每一頁分別檢查：任一頁缺少佔位符即中止，並指名是哪一頁。

**不採用「掃描所有 HTML 統計總數」**：本檔的 `REQUIRED_DATA` 已經對同一類問題做過決定，
註解寫著「刻意寫死而非掃目錄：掃目錄的話，來源檔被刪掉只會讓它不被列舉，組建照樣『成功』……
寫死才能讓缺檔當場失敗（決策四）」。總數計數會犯同一個錯——儀表板頁若失去佔位符，
而別處（例如日後 vendor 升級帶進來的 demo HTML）湊巧含有該字面字串，總數非零，
組建就會誤判成功。掃描還會碰到發佈規格「vendored libraries copied unchanged」的承諾。

明列清單同樣可擴充，且缺漏時能指名道姓，失敗訊息的品質不會退化。
本次的清單只有儀表板一頁；日後新增呈現單一期別的頁面時，須同時加入清單——
這與新增資料檔須同時加入 `REQUIRED_DATA` 是同一條紀律。

首頁（資料目錄）不在清單上——它呈現的是 25 筆各自的 `dataDate`，不存在單一基準日。
若強行給它一個，反而會製造「這一頁的資料截止於某日」的假象。

### 新首頁最顯著處必須有前往儀表板的入口

根網址已累積「這裡是儀表板」的外部認知，而 GitHub Pages 是靜態託管、無法做 301 轉址。
回訪者打開根網址看到的內容完全不同，若入口不明顯，合理的推論是「儀表板被移除了」。

故入口不放在頁尾或內文順帶一提，而放在首頁最上方的顯著位置，並說明它是什麼。
這不是文案偏好，是本次改動的直接後果。

### 補上首頁缺少的分享後設資料

`data.html` 目前只有 `og:type`／`og:site_name`／`og:locale`／`og:url`／`og:title`／
`og:description`，**沒有 `og:image` 與整組 twitter 標籤**——它原本是子頁，缺這些影響有限。
成為首頁後，缺 `og:image` 會讓分享卡片直接沒有圖。

本次補上這些標籤，沿用既有的 `og-image.png`。**卡片圖上的文字仍是舊文案**，
那是另一回事，記為已知落差（見下）。

### 頁面行為的驗證不能靠既有回歸測試

`tests/run-regression.ps1` 是資料轉檔的回歸測試：它建沙箱、跑 `build-population.ps1`、
斷言產出檔與自我驗證。它**不建站、不開瀏覽器、不碰任何頁面**。
把「四個面板與變更前相同」掛在它下面等於沒有驗證。

故本次新增一支建站 smoke 檢查：執行組建、服務發佈目錄、分別開啟三個位址，
檢查資源請求、主控台錯誤、面板與圖資行為，以及退場位址的回應狀態。

### 「首屏可見」以固定 viewport 驗證

「預設視窗高度」不可重現——瀏覽器、作業系統、桌機與手機都不同。
改為指定兩組 viewport（桌機 1280×800、行動 390×844），
以瀏覽器自動化取得入口元素的邊界框，確認完全落在視窗內，而非人工目測。

### 加入自訂 404 頁

`data.html` 變成 404 後，訪客會看到 GitHub Pages 的預設錯誤頁，沒有任何回站台的路徑。
加一個 `site/404.html` 指回資料目錄與儀表板。

這**不違反 Non-Goals 的「不做重新導向」**：自訂 404 頁不是轉址，它不會讓舊網址繼續有效，
只是讓走到死路的人有路可回。GitHub Pages 原生支援根目錄的 `404.html`。

### 兩頁互連的措辭要說出彼此是什麼

首頁指向儀表板時，不寫「儀表板」三個字了事，而要說明那是用其中幾份資料做的分析；
儀表板回指首頁時，說明那是完整的資料目錄。讀者從任一頁進來都應知道另一頁存在且為何存在。

### 分享卡片文案的來源隨首頁改變

`make-brand-assets.py` 的註解載明卡片文案必須與 `index.html` 的 `<h1>` 及 `.lede` 對應。
首頁換人之後，該對應關係指向的是資料目錄的標題與導言。本次更新註解與文案來源，
但**不重新產生圖檔**——圖檔的產生不屬於組建流程，且卡片圖上的文字與新文案不符
屬於已知落差，記在 README 而非靜默留著。

## Implementation Contract

**行為**：訪客開啟站台根網址看到資料目錄；開啟 `/dashboard.html` 看到四個面板且行為與
變更前相同（區域切換、下鑽、席次模擬、溯源彈窗）。兩頁各自可獨立使用，互有連結。

**介面**：不新增資料檔、不改變 `data/sources.json` 的結構、不改變前端讀取資料的路徑常數。
儀表板讀取的資料檔與變更前完全相同。

**失敗模式**：發佈目錄中所有 HTML 頁面的基準日佔位符總數為零時，組建中止並刪除發佈目錄，
訊息說明「站台必須至少有一處基準日由資料決定」。個別頁面沒有佔位符不構成失敗。

**驗收**：
- 根網址呈現 25 筆來源與 4 筆缺口，與變更前的 `data.html` 一致
- `/dashboard.html` 的四個面板、區域切換與席次模擬與變更前一致
- `/data.html` 回應 404
- 兩頁的 canonical 與 og:url 各自指向自己的網址，無交叉錯指
- 移除所有頁面的佔位符後組建中止；只移除首頁的（首頁本來就沒有）不影響組建
- README 的頁面清單與實際檔案一致

**範圍界線**：
- 範圍內：兩頁互換、互連文案、首頁定位文案與分享卡片後設資料、基準日檢查的對象、README
- 範圍外：儀表板與資料目錄各自的內容與行為、`sources.json`、重新導向、分享卡片圖檔重製

## Risks / Trade-offs

- **[根網址語意改變，既有外部連結會看到不同內容]** → 這是本變更的目的而非副作用。
  儀表板仍可到達，且首頁明確指向它。

- **[`data.html` 變成 404]** → 該網址存在不足一日，外部連結風險極低；
  相對於同一內容長期存在兩個網址，一次性的 404 代價較小。

- **[分享卡片圖檔的文字與新文案不符]** → 已知落差，記於 README。
  重新產生圖檔需要字型與繪圖環境，不屬於組建流程，故不納入本次。

- **[既有規格的 @trace 區塊仍列著 `site/index.html`]** → 全樹盤點結果為 **4 份規格共 11 處**
  （`data-pipeline`、`data-provenance`、`scheduled-data-refresh`、`site-deployment`），
  不只最初以為的三份。這些 trace 清單列有該路徑，更名後該檔案的內容已不是
  它們原本追溯的儀表板邏輯。trace 是註解不是行為，不阻斷任何事；但這是真實的落差，
  記在此處而非靜默留著。修正 trace 需重跑封存流程，不納入本次。

- **[邊緣快取使根網址短時間仍回舊內容]** → GitHub Pages 對 HTML 有分鐘級快取，
  置換後數分鐘內部分訪客可能仍看到儀表板。非正確性問題，會自癒，不做處理。
