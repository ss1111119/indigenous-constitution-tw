## 1. 頁面骨架與資料載入

- [x] 1.1 依 design 決策「頁面完全由資料產生，不手寫任何一筆內容」，滿足 The catalogue is generated from the source registry：新增獨立頁面，其來源條目全部由來源登記檔於載入時產生，頁面標記中不含任何來源名稱、機關或授權文字。驗證方式：以搜尋確認頁面原始碼不含任何來源的名稱或授權字串；並確認呈現的來源筆數等於登記檔中的筆數。

- [x] 1.2 登記檔載入失敗時，頁面指出載入失敗與缺少的檔案，與站台既有面板的錯誤處理一致，不以空表或空白呈現。驗證方式：以指向不存在路徑的方式載入頁面，確認顯示失敗訊息並含檔名。

- [x] 1.3 頁面取用資料的路徑沿用站台既有的資料基底路徑常數，不另行定義第二個路徑定義。驗證方式：以搜尋確認頁面程式未出現自訂的資料路徑字面值。

## 2. 授權的雙軌呈現

- [x] 2.1 依 design 決策「授權必須拆成兩個獨立事實呈現」，滿足 Licence grant and this project's reuse judgement are shown as separate facts：每筆同時呈現提供者的授權宣告與本專案的再利用判斷，兩者不合併為單一結論；再利用判斷不呈現為給讀者的授權。驗證方式：以 delta spec 的四列表格逐列比對實際呈現。

- [x] 2.2 兩者不一致時（授權宣告非開放授權、再利用判斷為可再利用），呈現指向該筆自身的說明。驗證方式：檢視 cip-monthly-population-11506 一筆，確認同時顯示「非開放授權」與本專案判斷，並有指向該筆說明的提示。

- [x] 2.3 再利用判斷的三種值分別可辨，未定不得被呈現為可或不可。驗證方式：比對 capas-tpdd（不可）、capas-tipd（未定）與任一可再利用者，確認三者呈現互不相同。

## 3. 檢視與分區

- [x] 3.1 依 design 決策「自動化狀態由既有欄位導出，不新增欄位」，滿足 Sources that cannot be tracked automatically are identifiable without opening each entry：讀者不展開個別條目即可看出哪些來源具備程式介面，且該檢視明示「缺乏的原因記於各筆說明」。驗證方式：在不展開任何條目的情況下清點具備與不具備程式介面的筆數，並確認檢視含該說明文字。

- [x] 3.2 滿足 Data gaps are presented apart from usable sources：資料缺口以獨立區塊呈現，不與來源混列，且每筆缺口顯示其成因與「不得以何種方式替代」。驗證方式：確認四筆缺口全數呈現於獨立區塊，且各自的禁止事項可讀。

## 4. 原文與無腳本可用性

- [x] 4.1 依 design 決策「原文 notes 完整呈現，預設收合」，滿足 Entry accounts are shown in full：每筆的原文說明完整可讀，未截斷、未摘要、未改寫，預設收合且收合不依賴腳本。驗證方式：展開最長的一筆（約 2,826 字）逐字比對登記檔內容；並停用 JavaScript 確認收合控制仍可展開。

- [x] 4.2 停用 JavaScript 時頁面說明目錄列表需要腳本，且標題與入口連結仍可讀。驗證方式：停用 JavaScript 載入頁面，確認說明文字出現且頁面不是一片空白。

## 5. 入口與整體確認

- [x] 5.1 依 design 決策「獨立頁面，不併入首頁的分頁切換」，首頁加入通往目錄頁的連結，且首頁的初始載入不因此包含來源登記檔。驗證方式：載入首頁後檢視實際發出的網路請求，確認未請求登記檔；並確認連結可達目錄頁。

- [x] 5.2 目錄頁進入發佈目錄且線上可達，既有頁面未受影響。驗證方式：執行組建後確認產物含新頁面，並以瀏覽器檢視首頁四個面板與目錄頁皆正常。
