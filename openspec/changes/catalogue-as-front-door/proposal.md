## Why

這個專案的主張是**臺灣原住民族開放資料**——盤點資料在哪、授權能不能用、有什麼陷阱、
能不能自動追蹤，以及哪些資料根本不存在。儀表板的四個面板是用其中幾份資料做出來的分析，
是這個主張的佐證，不是主張本身。

站台目前的結構把兩者反過來：根網址是儀表板，資料目錄的入口是頁尾「資料來源」段落裡的
一句話——在 245 行的頁面中位於第 207 行。一個以開放資料為主題的站台，
把它的資料盤點放在最後一個區塊裡順帶一提。

首頁的標題與導言也只描述分析（「憲政代表性與土地資料……做的是整合與計算」），
沒有提到盤點本身，因此從搜尋結果或分享卡片進來的人不會知道這裡有一份資料目錄。

## What Changes

- 資料目錄成為站台首頁；儀表板移至獨立網址，成為子頁。
- 首頁的標題、導言、分享卡片文案改為描述資料盤點，並說明儀表板是其中幾份資料的分析。
- 兩頁互相連結：首頁指向儀表板，儀表板指回首頁。
- 組建流程的基準日檢查改為指向儀表板頁，而非固定檢查名為 index.html 的檔案；
  該檢查原本要防的事（基準日不得回到寫死狀態）必須維持成立。
- 根網址的語意改變：原本是儀表板，改為資料目錄。canonical 與分享卡片的網址一併更正。

## Non-Goals

- **不改變儀表板本身的內容與行為。** 四個面板、區域選擇器、席次模擬器一律不動，
  只換所在網址與互連方式。
- **不改變資料目錄頁的內容與行為。** 本次只改它的位置與周邊文案。
- **不改 `data/sources.json`。** 定位改變不影響登記檔。
- **不做重新導向。** GitHub Pages 的靜態託管沒有伺服器端重新導向；
  以 HTML meta refresh 假造會讓兩個網址同時存在且內容相同，對搜尋引擎與使用者都更糟。
  外部若有指向根網址的既有連結，改後會看到資料目錄——那正是本變更要的結果。
- **不重寫可行性研究。** 該報告是 2026-08-09 的快照且自述不隨後續工作更新；
  本變更是定位決定，不追溯修改當時的判斷紀錄。

## Success Criteria

- 開啟站台根網址看到的是資料目錄，且其內容與變更前的 data.html 相同。
- 儀表板在自己的網址上完整運作：四個面板、區域切換、席次模擬與變更前一致。
- 兩頁可互相到達，且任一頁都不需要先經過另一頁才能使用。
- 首頁的標題與導言描述的是資料盤點，且提及儀表板的存在。
- 分享卡片與 canonical 的網址與各自頁面實際所在的網址一致，不互相指錯。
- 組建流程仍會在儀表板頁缺少基準日佔位符時中止，並說明原因；
  首頁沒有該佔位符不構成失敗，因為資料目錄沒有單一基準日。

## Capabilities

### New Capabilities

（無）

### Modified Capabilities

- `site-deployment`：基準日佔位符的檢查對象由「index.html」改為「呈現單一期別資料的頁面」，
  並明訂站台可有一個以上的頁面。
- `dashboard-shell`：儀表板不再位於站台根網址，其入口與回返路徑需明確定義。

## Impact

- Affected specs: `site-deployment`、`dashboard-shell`
- Affected code:
  - New: site/404.html（退場網址的回站路徑）
  - Modified: site/index.html（更名自 data.html 並補上分享後設資料與儀表板入口）、
    site/dashboard.html（更名自 index.html）、scripts/build-site.py（必含佔位符的頁面清單）、
    scripts/make-brand-assets.py（分享卡片文案來源）、README.md（頁面清單、目前階段敘事、
    本機預覽說明、已知落差）、tests/（新增建站與頁面 smoke 檢查）
  - Removed: site/data.html（內容更名為 index.html，該路徑不再存在）
