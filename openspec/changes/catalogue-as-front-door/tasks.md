## 2. 互連與後設資料

- [x] 2.1 依 design 決策「兩頁互連的措辭要說出彼此是什麼」，首頁指向儀表板時說明那是用其中幾份資料做的分析，儀表板回指首頁時說明那是完整的資料目錄。驗證方式：內容審閱兩處連結文字，確認皆非只有名稱。

- [x] 2.2 滿足 The site's entry page presents the data catalogue 的位址宣告要求：兩頁的 canonical 與分享用後設資料各自指向自己所在的網址，無交叉錯指。驗證方式：檢視兩頁的 canonical 與 og:url，與各自的實際路徑逐一比對。

- [x] 2.3 首頁的標題與導言描述資料盤點而非僅描述分析，且提及儀表板存在。驗證方式：內容審閱首頁標題與導言。

- [x] 2.4 依 design 決策「新首頁最顯著處必須有前往儀表板的入口」，滿足 The site's entry page presents the data catalogue 的回訪者要求：儀表板入口位於首頁上方、不需捲動即可看見，且說明儀表板是什麼。驗證方式：依 design 決策「「首屏可見」以固定 viewport 驗證」，在桌機 1280×800 與行動 390×844 兩組視窗下載入首頁，取得該入口元素的邊界框，確認完全落在視窗內，並確認其文字說明儀表板是什麼。

- [x] 2.5 依 design 決策「補上首頁缺少的分享後設資料」，首頁具備分享圖與 twitter 卡片標籤，沿用既有的分享圖檔。驗證方式：檢視首頁標記，確認 og:image 與 twitter 卡片標籤齊備且圖檔路徑可解析。

## 3. 組建流程

- [x] 3.1 依 design 決策「基準日檢查改為明列「必須含佔位符的頁面」清單」，滿足 The publish build performs exactly one kind of substitution：組建對清單上每一頁分別檢查佔位符，任一頁缺少即中止、刪除發佈目錄並【指名是哪一頁】；不在清單上的頁面沒有佔位符不構成失敗。不得改以掃描發佈目錄統計總數實作。驗證方式：正常組建成功且回報取代處數；暫時移除儀表板頁的佔位符後組建中止且訊息含該頁名稱；另確認首頁（不在清單上）沒有佔位符時組建仍成功。

- [x] 3.2 依 design 決策「分享卡片文案的來源隨首頁改變」，產生分享卡片的腳本其文案對應關係指向新的首頁，並在 README 記明現有卡片圖檔的文字與新文案不符為已知落差。驗證方式：內容審閱該腳本的對應說明與 README 的落差記載。

- [x] 3.3 依 design 決策「加入自訂 404 頁」，滿足 A missing address leads back into the site：站台發佈自己的 404 頁，連向資料目錄與儀表板。其連結須在任何位址下都解析得到，包含站台從未提供的巢狀路徑——頁面相對連結會相對於缺失位址的目錄解析而走不到，而本站發佈於路徑前綴之下、以伺服器根開頭的連結會離開站台。驗證方式：組建後確認發佈目錄含該頁；並實測退場位址與一個巢狀不存在位址，確認兩者都顯示該頁、連結都到得了目錄與儀表板、且回應狀態為 404 而非 200。

- [ ] 3.3b 滿足 Deployment is automated from the default branch 修正後的根位址描述：部署後 Pages 根位址提供的是資料目錄而非儀表板，且路徑不含 /site/ 區段。workflow 本身不需改動（它只跑組建並上傳整個發佈目錄），本項確認的是實際部署結果與規格一致。驗證方式：部署完成後開啟線上根位址與儀表板位址各一次，比對內容與路徑。

- [x] 3.4 README 的頁面清單與實際檔案一致，含新的兩個頁面與各自用途。此外 README 的「目前階段」敘事目前把儀表板寫成站台的主產出、隻字未提資料目錄，須改為與新定位一致；本機預覽段落提到開啟根位址之處也須說明那是資料目錄。並記明既有分享圖檔的文字與新文案不符、以及三份規格的 @trace 仍列著舊路徑兩項已知落差。驗證方式：比對 README 所列頁面與 site/ 下的實際 HTML 檔案，並內容審閱上述三段敘述。

## 4. 規格措辭與既有行為

- [x] 4.0 三條需求的措辭改為指向面板頁而非站台整體，並以實際行為驗證：Global region selector is the only shared state（區域選擇器只在面板頁、資料目錄不共享任何區域狀態）、Load township geometry only when needed（開啟資料目錄不請求任何圖資，開啟面板頁只請求縣市層級）、The data base path has exactly one definition（全站每一頁的標記皆無父層相對資料路徑，不限於單一檔名）。驗證方式：載入兩頁各自檢視實際發出的網路請求；並以搜尋確認 site/ 下所有頁面與 site/js/ 皆無該字面路徑。

## 5. 整體確認

- [x] 5.1 兩頁在本機預覽下皆可獨立使用且互相到達，主控台無錯誤。驗證目標：兩頁的畫面比對與主控台輸出。

- [x] 5.2 資料轉檔的既有行為未因本變更改變。驗證目標：`pwsh tests/run-regression.ps1` 離開碼。此項【不涵蓋】頁面行為——該腳本不建站、不開瀏覽器，見 5.3。

- [x] 5.3 依 design 決策「頁面行為的驗證不能靠既有回歸測試」，新增建站 smoke 檢查：執行組建、服務發佈目錄，分別開啟根位址、儀表板位址與一個不存在的位址，檢查資源請求、主控台無錯誤、四個面板與圖資行為，以及不存在位址的回應狀態為 404。驗證目標：該檢查的離開碼與各項斷言。

- [x] 5.4 組建對清單上的頁面須先確認其存在，而非只在存在時檢查佔位符——清單列了一個不存在的頁面時組建須中止並指名該頁。驗證方式：暫時在清單中加入一個不存在的檔名，確認組建中止且訊息含該檔名。
