## Context

四張圖表由三個面板模組各自建立：`site/js/panel-population.js` 的族別長條圖、`site/js/panel-election.js` 的投票率圖與倍數差距圖、`site/js/panel-land.js` 的所有權逐年圖。四者都是 `document.createElement('canvas')` 加 `new window.Chart(canvas, config)`，且都沒有設定任何 `role` 或 `aria-label`。

`site/js/panel.js` 是既有的共用模組，匯出 `createPanel`、`fmt`、`natureTag`。

四張圖傳給 Chart.js 的 `data` 物件結構一致：`labels` 是類別或年份的陣列，`datasets` 是一或多個序列，每個序列有 `label`（族別長條圖的單一序列沒有 `label`）與 `data` 陣列。資料缺口在 Chart.js 中以 `null` 表示——投票率圖以 `?? null` 產生，土地圖的民國 108、109 年同理。這一點很重要：**缺口在資料層就已經與 0 分開了**，`null` 是無資料、`0` 是零。

限制條件：維持零 npm 相依、不動 vendored Chart.js、不改任何圖表的視覺呈現。

`data-provenance` 既有的 requirement「Distinguish absent data from zero」規定「the interface SHALL render three states differently」。表格是 interface 的一部分，因此本 change 不新訂三態規則，而是必須滿足既有規則。

## Goals / Non-Goals

**Goals:**

- 讀不到 canvas 的人能取得四張圖的全部數值。
- 表格與圖表在結構上不可能不一致。
- 三個面板不各自實作一套表格邏輯。
- 「無資料」與「0」在表格中可區辨，且此區辨不依賴實作者記得要處理。

**Non-Goals:**

- 半圓席次圖（已合規）與地圖（另開 change）。
- 排序、篩選、匯出。
- 引入測試框架或無障礙檢測工具鏈。
- 改動圖表視覺、資料內容或轉檔腳本。

## Decisions

### 決策一：表格由傳給 Chart.js 的同一個 data 物件推導

共用建構函式接受即將傳給 Chart.js 的 `data` 物件（`labels` 與 `datasets`），輸出對應的表格：`labels` 成為第一欄的列標題，每個 dataset 成為一個資料欄。

替代方案是各面板依自己的來源陣列另外組表格（族別長條圖用 `bars`、土地圖用逐年陣列）。否決原因：那會有兩條各自獨立的路徑從同一份資料算出「圖上的數字」與「表裡的數字」，兩者可以在不被察覺的情況下分歧——改了圖的資料處理卻忘了改表，表格就開始說謊。而表格存在的理由正是給想驗算的人看，說謊的表格比沒有表格糟。

以同一個物件推導，圖表與表格的數值來自同一個陣列，結構上不可能不一致。

### 決策二：`null` 一律渲染為無資料標記，`0` 一律渲染為 0

建構函式對 `null` 與 `undefined` 輸出無資料標記，對數值 `0` 輸出 `0`。這個判斷寫在共用函式內，不交由各呼叫端處理。

理由是 `data-provenance` 的三態要求若靠「每個實作者記得要分」來滿足，遲早會漏；寫在共用路徑上則是每張表自動滿足。土地圖的民國 108、109 年因此自動顯示為無資料，不需要土地面板做任何額外處理。

### 決策三：`details` 收合表格，同時為 canvas 加上 `role` 與 `aria-label`——兩者並用

表格放在 `details` 內預設收合，沿用專案剛建立的漸進揭露樣式。**但收合狀態的 `details` 內容不在無障礙樹中**，所以 `details` 不能是唯一的替代：canvas 另外取得 `role="img"` 與摘要性的 `aria-label`，說明該圖呈現什麼、涵蓋哪些類別與期間。

於是無障礙路徑是兩段的：`aria-label` 提供「這是什麼圖」的即時摘要，`details` 提供可主動展開的完整數值。`details` 與 `summary` 本身是可鍵盤操作、會被輔助技術宣告為可展開元件的原生控制項，因此展開這件事對螢幕閱讀器使用者是可達的。

替代方案是把表格以 clip 型 visually-hidden CSS 永遠渲染，使其恆在無障礙樹中。否決原因：那樣視覺使用者若想看表格就需要另一份可見的複本，同一份內容在 DOM 中出現兩次；或者不提供可見版本，讓表格變成只給輔助技術的隱藏內容——而「想驗算的人」不限於使用輔助技術的人，可見的表格對所有人都有用。單一份可展開的表格同時服務兩者。

### 決策四：單位與數值格式由呼叫端提供

三種圖的單位不同：人數、百分比、倍數。建構函式接受一個格式化函式，由各面板提供（人數用既有的 `fmt`，百分比與倍數各自帶小數位與單位）。

替代方案是讓建構函式自行猜測單位。否決原因：猜不出來，且猜錯會產生看起來合理但錯誤的表格。

### 決策五：共用建構函式放在 `site/js/panel.js`

該檔已是三個面板共同匯入的模組，放這裡不需要新增檔案，也不需要面板之間互相匯入。

## Implementation Contract

**行為**

- 四張 canvas 圖表各自具有 `role="img"` 與非空的 `aria-label`，內容摘要該圖呈現什麼與涵蓋範圍。
- 四張圖表下方各有一個預設收合的可展開區塊，展開後顯示該圖所有資料點的表格。
- 表格第一欄為類別或年份，其餘每欄對應圖上一個序列。
- 資料缺口顯示為明確的無資料標記；值為 0 顯示為 0。兩者在文字上不同。
- 圖表的視覺呈現與互動完全不變。

**介面**

- `site/js/panel.js` 新增一個匯出的具名函式，接受即將傳給 Chart.js 的 `data` 物件、一個標題字串、第一欄的欄名、以及一個把數值轉為顯示字串的格式化函式；回傳一個含 `details`、`summary` 與 `table` 的 DOM 元素。
- 呼叫端在建立 Chart 實例前後皆可呼叫，順序不影響結果——函式只讀 `data`，不接觸 Chart 實例。
- 無資料標記為一個固定字串常數，定義於 `site/js/panel.js`，四張表一致。

**失敗模式**

- `datasets` 為空陣列 → 產生只有列標題欄的表格，不拋錯。
- 某個 dataset 的 `data` 長度短於 `labels` → 缺少的位置視為無資料，不拋錯、不對齊錯位。
- 格式化函式未提供 → 以字串轉換輸出原值，不拋錯。此為退化行為而非正常用法。

**驗收條件**

- 於瀏覽器查詢頁面上全部 `canvas` 元素，四者皆有 `role="img"` 且 `aria-label` 長度大於 0。
- 四個圖表各有一個表格。每張表的資料列數等於該圖 `labels` 的長度；資料欄數等於 `datasets` 的長度加一。
- 土地表格中民國 108 年與 109 年兩列的所有數值欄皆顯示無資料標記，且該標記不等於字串 `0`、不為空白。
- 人口面板族別表格中所有數值欄加總等於面板標題所示的原住民族人口總數。
- 以組建出的 `_site/` 服務並切換四個分頁，各圖表視覺呈現與改動前一致（軸、色階、圖例、資料點、土地圖的 108–109 斷線皆不變）。
- 展開表格後圖表仍正常，收合後亦然；瀏覽器 console 無錯誤。

**範圍邊界**

- 在範圍內：`site/js/panel.js` 新增共用建構函式與無資料標記常數、三個面板模組各自為 canvas 加上 `role` 與 `aria-label` 並插入表格、`site/css/main.css` 新增表格與其摺疊容器的樣式。
- 不在範圍內：半圓席次圖、地圖、排序篩選匯出、測試或檢測工具鏈、圖表視覺、資料內容、轉檔腳本。

## Risks / Trade-offs

- **收合的 `details` 內容不在無障礙樹中，若只做 `details` 等於沒解決問題** → 決策三明訂 `role="img"` 與 `aria-label` 必須同時存在；驗收條件把「四個 canvas 皆有非空 `aria-label`」列為獨立的機械檢查，不倚賴「有做表格就算完成」。
- **表格與圖表分歧** → 決策一從同一個 `data` 物件推導，使分歧在結構上不可能發生，而非靠實作紀律避免。
- **三態區辨被漏掉** → 決策二把 `null` 到無資料標記的映射寫在共用路徑上，各面板無法繞過也無需記得。
- **`aria-label` 的內容品質無法機械檢查** → 只能驗證非空。內容是否真的有用需人工判讀，這一點明確承認；驗收條件要求逐一閱讀四個 `aria-label` 而非只檢查長度。
- **四張表增加頁面高度** → 預設收合，收合狀態下只多一行 `summary`。
